# نظام تسجيل الـ SOP (Standard Operating Procedures)

نظام مستقل لتسجيل تعليمات التشغيل القياسية بشكل SOP احترافي متكامل، مطابق لعناصر مستند SOP القياسي:

```
SOP
 ├── 1) البيانات الأساسية (كود تلقائي، إصدار، الخط، إعداد/اعتماد تلقائي بالاسم والتاريخ)
 ├── 5-6) الخطوات (مباشرة بعد الخط — مفيش مستوى "مراحل" وسط، اتشال):
 │        ├── المعدات والآلات المستخدمة + مهمات وإجراءات الوقاية (جنب بعض)
 │        ├── شرح الخطوة + صورة الخطوة
 │        ├── معيار القبول + طريقة الفحص + التكرار + الإجراء عند الرفض
 │        └── وسم "خطوة حرجة" لو لازم وقفة إلزامية
 ├── معدات وإجراءات السيفتي — بتتكتب مرة واحدة في البيانات الأساسية وتتكرر تلقائيًا جنب كل خطوة في التقارير
 ├── 8) التعامل مع الانحرافات — في قسم "تفاصيل إضافية" بعد الخطوات
 ├── 4) الأدوات والمواد المطلوبة (عامة على مستوى الـ SOP)
 ├── 9) المراجع (معايير / رسومات هندسية)
 └── 10) سجل التعديلات — بيزيد رقم الإصدار (Rev.) بس لما تدوس زرار "💾 حفظ التعديلات"
```

مع زرين طباعة (تفصيلي وجدول Excel-style)، لوجو شركة يتضاف مرة واحدة من داخل النظام ويظهر تلقائيًا في كل مكان، وفوتر ثابت (كود الفورم) بيتكرر في كل صفحة مطبوعة.

الستاك: Supabase (DB + Auth + Storage) + JavaScript عادي (بدون build step) + GitHub Pages — نفس نمط مشاريعك التانية.

   ```js

   ```

### الأدوار (Roles)
كل حساب جديد بيتسجل بصلاحية `viewer` تلقائيًا (مشاهدة فقط). عشان تدي حد صلاحية `editor` أو `admin`:

```sql
update public.profiles set role = 'admin' where id = 'USER_UUID_HERE';
```

هتلاقي الـ UUID من **Authentication > Users** في Supabase Dashboard.

- **viewer**: يشوف ويطبع بس.
- **engineer** (أو **editor** القديم لسه شغال بنفس الصلاحيات): يضيف/يعدل SOPs، خطوات، صور، وبيبعت الـ SOP للمراجعة.
- **head**: يراجع الـ SOPs اللي اتبعتت (موافقة → تتبعت للدايركتور، أو رفض → ترجع للمهندس).
- **director**: الاعتماد النهائي — بعد موافقته بيتزوّد رقم الإصدار (Rev.) تلقائيًا ويتسجل في سجل التعديلات.
- **admin**: صلاحيات كل الأدوار مجمّعة + حذف SOP كامل + إدارة اللوجو.

**سايكل الموافقات:** المهندس يعمل SOP ويحفظه، يدوس "📤 إرسال للمراجعة" → إشعار بيروح لكل الـ heads → الهيد يوافق أو يرفض (مع ملاحظة اختيارية) → لو وافق بيروح إشعار لكل الـ directors → الدايركتور يعتمد اعتماد نهائي (بيزوّد الإصدار تلقائيًا) أو يرفض. أي رفض بيرجع الـ SOP لحالة "مسودة" مع الملاحظة ظاهرة للمهندس، وكل خطوة في السايكل بتتسجل في "لوج الاعتمادات" (مين وامتى) في صفحة التعديل.

**الإشعارات:** جرس 🔔 فوق يمين التوب بار — بيوريك عدد الإشعارات غير المقروءة، ودوسة عليه بتفتح قائمة بكل الإشعارات مع لينك مباشر للـ SOP.

## 2. تشغيل محلي / رفع على GitHub Pages

مفيش build step — الموقع HTML/CSS/JS عادي.

**محلي:** افتح المجلد بأي static server (مثلاً إضافة Live Server في VS Code) أو:
```bash
npx serve .
```

**GitHub Pages:**
1. ارفع محتوى المجلد كامل (`index.html`, `css/`, `js/`) لريبو جديد على GitHub.
2. Settings > Pages > اختار الـ branch (main) و root.
3. خلال دقيقة الموقع هيبقى شغال على `https://username.github.io/repo-name/`.

## 4. طريقة الاستخدام

1. سجّل حساب (Sign up) من الصفحة الرئيسية.
2. اطلب من نفسك (أو من admin) ترقية صلاحيتك لـ editor عن طريق SQL query فوق.
3. من "+ SOP جديد" هيتفتح فورم بسيط: اكتب **اسم الخط** (مثال: "التجميع النهائي")، احفظ — الكود بيتولّد لوحده على طول (زي `SOP-FINAL-ASSEMBLY-001`).
4. اكتب كل حاجة (البيانات الأساسية، الخطوات، التفاصيل الإضافية) وانزل لآخر الصفحة، هتلاقي **زرار واحد بس** لكل الفورم: **"💾 حفظ وإرسال للمراجعة"**. الزرار ده بيحفظ كل حاجة كتبتها في الصفحة كلها دفعة واحدة، بيزوّد رقم الإصدار (Rev.)، وبيبعت الـ SOP على طول للهيد للمراجعة. مفيش زراير حفظ منفصلة تانية في أي قسم (غير زراير "+ إضافة" للأدوات/المراجع والصور، دي بتتحفظ فورًا لإنها إضافة عنصر مش تعديل نص).
5. تحت كده على طول قسم **خطوات التشغيل** — زرار "+ إضافة مرحلة جديدة" بيضيفلك أول خطوة فيها تلقائيًا تكتب فيها على طول. جوه كل خطوة: العنوان، **المعدات والآلات المستخدمة** و**مهمات وإجراءات الوقاية (السيفتي)** جنب بعض، شرح الخطوة، صورة الخطوة، معيار القبول، طريقة الفحص، التكرار، الإجراء عند الرفض.
6. تحت الخطوات، قسم **"تفاصيل إضافية"** (السلامة العامة/الانحرافات)، وبعده **الأدوات والمواد** و**المراجع** — اختياريين، تقدر تملاهم في أي وقت.
7. من **admin** تقدر تدوس **"✅ اعتماد الـ SOP"** — بيسجّل اسمك وتاريخ اليوم تلقائيًا كتاريخ اعتماد، ويطلع مطبوع على الورقة.
8. اضغط "عرض / طباعة" لمعاينة الشكل النهائي، وهتلاقي زرارين طباعة:
   - **"طباعة / PDF"**: نسخة تفصيلية كاملة (ممكن تمتد لأكتر من صفحة).
   - **"📊 نسخة الجدول (Excel)"**: جدول أفقي — صف لكل خطوة، وكل تفصيلة في خانة منفصلة، بالظبط زي شيت إكسيل. الصور بحجم موحّد وواضح، والتقرير بيمتد لأكتر من صفحة تلقائيًا لو الخطوات كتيرة.

**الترجمة التلقائية:** أي حقل عنوان بالعربي (اسم الـ SOP / المرحلة / الخطوة) — لما تكتبه وتخرج منه، لو حقل الإنجليزي جنبه فاضي هيتترجم تلقائيًا (خدمة مجانية بدون مفتاح API). لو الترجمة مش دقيقة تقدر تعدلها يدوي في أي وقت.

**الكود التلقائي:** مفيش إدخال يدوي لكود المستند ولا لتاريخ الإعداد ولا لاسم اللي بيعمل التعديل. اكتب اسم الخط واحفظ، والنظام بيولّد كود زي `SOP-FINAL-ASSEMBLY-001` تلقائيًا. "أنشأ بواسطة" و"آخر تعديل بواسطة" بياخدهم النظام من حساب المستخدم المسجّل دخول تلقائيًا.

**ترتيب حقول الخطوة** بقى: 1) الخطوة 2) المعدات والآلات المستخدمة + السيفتي جنب بعض 3) شرح الخطوة 4) صورة الخطوة 5) معيار القبول 6) طريقة الفحص 7) التكرار 8) الإجراء عند الرفض. حقل "معيار الرفض" اتشال خالص (معيار القبول بيغطيه). أي بيانات إضافية (المسؤول، المواصفة الفنية، كود العيب، الفيديو) في قسم "بيانات إضافية (اختياري)" قابل للطي.

**هيكل مبسّط بمستويين بس:** SOP ← خطوات مباشرة — مفيش "مراحل" وسيطة خالص. تدخل بيانات الـ SOP (الخط، الكود بيتولّد لوحده، السيفتي، الفيديو...)، وعلى طول تبدأ تكتب الخطوات واحدة ورا التانية بزرار "+ إضافة خطوة جديدة". لو عندك SOPs قديمة كانت متقسمة على أكتر من مرحلة، النظام بيدمجهم تلقائيًا في قائمة خطوات واحدة أول ما تفتح صفحة التعديل بتاعتها (من غير ما يفقد أي خطوة).

**السيفتي بقى مرة واحدة بس:** معدات وإجراءات الوقاية بتتكتب مرة واحدة في البيانات الأساسية للـ SOP، وبتتكرر تلقائيًا جنب كل خطوة في صفحة العرض والتقارير المطبوعة (التفصيلي والجدول) — مش محتاج تكتبها لكل خطوة لوحدها.

**فيديو الـ SOP:** فيديو واحد بس لكل SOP (مش لكل خطوة) — هتلاقي حقله في البيانات الأساسية فوق. تقدر إما تلصق رابط فيديو خارجي (يوتيوب/درايف)، أو تدوس "📹 رفع فيديو" وترفع ملف مباشرة من جهازك (بيتخزن في Supabase Storage). بيظهر في صفحة العرض كرابط، وفي الطباعة كـ QR code مرة واحدة فوق الصفحة.

**رقم المحطة وفلو الخط:** كل SOP بيمثل محطة على خط إنتاج، فدلوقتي كل SOP ليه حقل "رقم المحطة على الخط" (رقم صحيح، لازم يكون فريد جوه نفس "الخط" — لو كررت رقم موجود قبل كده في نفس الخط هيرفض الحفظ ويطلعلك تنبيه). في **صفحة قائمة الـ SOPs (الداشبورد)**، هتلاقي فوق قسم "فلو الخط" — اختار الخط من الـ dropdown، وهيرسملك كل الـ SOPs (المحطات) بتاعته كصناديق مرتبطة بأسهم **مرتبة حسب رقم المحطة**، وكل صندوق لينك يودّيك مباشرة لصفحة الـ SOP بتاعه.

**لوجو الشركة:** من صفحة قائمة الـ SOPs، الـ admin بس بيشوف قسم "لوجو الشركة" فوق — دوس "رفع اللوجو" واختار الصورة **مرة واحدة بس**. بعد كده هيظهر تلقائيًا على يسار كل ورقة مطبوعة (تفصيلية أو جدول) في كل الـ SOPs، من غير ما تحتاج تضيفه تاني.

**الفوتر الثابت:** تحت كل صفحة مطبوعة (في التقريرين الاتنين) بيتحط سطر ثابت: "Midea Electric Egypt — FR-08-05-01-05 — Issue: 1.0 — ISO 9001:2015"، بيتكرر في كل صفحة تلقائيًا. لو حبيت تغيّره، هتلاقيه في دالة `buildFormFooter()` في `js/pdf-export.js`.

**إدارة المستخدمين من الموقع نفسه:** الأدمن بس بيشوف رابط "👥 المستخدمون" في التوب بار. من الصفحة دي تقدر:
- تنشئ حساب جديد (إيميل + باسورد تختاره إنت) وتبعته للمستخدم يدويًا عشان يسجّل دخوله بيهم
- تعدّل اسم أو صلاحية أي حساب موجود مباشرة من جدول بسيط

⚠️ **الميزة دي محتاجة خطوة نشر إضافية (Edge Function)** — عشان إنشاء حساب بباسورد محدد من غير ما المستخدم يسجّل نفسه محتاج صلاحيات خاصة (service role) متسمحش تتحط في كود الموقع لأسباب أمان، فلازم تشتغل من سيرفر Supabase نفسه:

1. من Supabase Dashboard، افتح **Edge Functions** من القائمة الجانبية
2. دوس **"Create a new function"** واكتب الاسم بالظبط: `admin-create-user`
3. امسح أي كود موجود، وافتح ملف `supabase/functions/admin-create-user/index.ts` من المشروع، انسخ محتواه كامل، والصقه
4. دوس **Deploy**

مفيش أي متغيرات (secrets) محتاج تضيفها يدوي — الـ Edge Function بتاخدها تلقائيًا من نفس مشروع Supabase.

**عرض عام لصفحة الـ SOP (لدعم مسح QR):** صفحة عرض أي SOP بقت متاحة لأي حد معاه اللينك المباشر، **حتى من غير تسجيل دخول** — عشان لما حد يمسح كود QR بموبايله، الصفحة تفتحله على طول (عرض بس، من غير أي إمكانية تعديل، ومع مشغّل الفيديو شغال عادي). التعديل والحذف وباقي الصفحات لسه محتاجة تسجيل دخول وصلاحية زي ما هي.

**كود QR بقى بيودّي لصفحة النظام نفسها** (مش رابط الفيديو مباشرة) — يعني لو مسحته هيفتحلك نفس صفحة عرض الـ SOP اللي إنت شايفها في المتصفح، بكل تفاصيلها، وتقدر تشغّل الفيديو منها مباشرة.

**زرار ترجمة الواجهة (🌐 EN/AR):** موجود دلوقتي في التوب بار في **كل صفحات الموقع** (الداشبورد، التعديل، العرض، إدارة المستخدمين...). بيترجم **عناوين الأقسام واللابلز والأزرار فقط** (يعني "شكل" الموقع)، **مش** محتوى البيانات اللي بتكتبها إنت (زي متطلبات العمل أو أسماء المعدات) — ده مختلف تمامًا عن زرار "🌐 English" التاني اللي جوه صفحة عرض الـ SOP، وده بيترجم محتوى الـ SOP نفسه. اللغة بتتحفظ في المتصفح (localStorage) فمش هترجع عربي كل مرة تفتح الموقع.
> ملاحظة: القاموس بيغطي أهم العناوين واللابلز في الصفحات الرئيسية. لو لقيت أي نص لسه عربي وعايزه يترجم، قولي النص بالظبط وأضيفه.

**نسخ SOP كاملة:** زرار **"📋 نسخ"** موجود في كارت أي SOP بالداشبورد، وكمان في صفحة عرضها ("📋 نسخ لمصنع تاني"). بيسألك عن اسم مصنع (اختياري — سيبه فاضي لو عايز نفس المصنع)، وبينسخلك الـ SOP **كاملة** (كل الخطوات، الصور، الأدوات، المراجع، بيانات السلامة...) كـ SOP جديدة منفصلة (مسودة، إصدار v1، بدون كود لحد ما تحفظ اسم خط جديد)، وبيوديك على طول لصفحة تعديلها عشان تظبط اللي محتاج تغيير (زي اسم الخط ورقم المحطة) بدل ما تبنيها من الأول.

## 5. ملاحظات فنية

- **الصور** بتتخزن في Supabase Storage bucket اسمه `sop-images` (public bucket، الرابط بيتحفظ في جدول `step_images`).
- **الفيديو** مش بيترفع على النظام — بس رابط خارجي (YouTube / Google Drive) بيتحط في العمود `video_url`، وبيظهر كـ QR code في نسخة الـ PDF.
- **الطباعة**: بتستخدم `jsPDF` + `html2canvas` لعمل A4 PDF فيه كل المراحل والخطوات والصور. لو عندك عدد صور كبير جدًا في SOP واحد، التصدير ممكن ياخد كذا ثانية — فيه progress message بيتغير على الزرار نفسه.
- **RLS**: أي مستخدم مسجل دخول (authenticated) يقدر يقرأ كل الـ SOPs. الكتابة (إضافة/تعديل/حذف) محصورة على `editor` و `admin` بس، عن طريق `is_editor_or_admin()` function جوه الـ policies.

---

**فلو الخط والمسارات الموازية:** في صفحة قائمة الـ SOPs، فوق كل محطة في "فلو الخط" هتلاقي 4 زراير "+" صغيرة (فوق/تحت/يمين/شمال):
- **يمين** = يضيف SOP جديدة **قبل** المحطة دي في التسلسل (بيزوّد أرقام كل اللي بعدها تلقائيًا)
- **شمال** = يضيف SOP جديدة **بعد** المحطة دي في التسلسل
- **فوق/تحت** = يضيف SOP جديدة تشتغل **بالتوازي** مع المحطة دي في نفس نقطة الخط (نفس رقم المحطة، مسار تاني)

أي زرار منهم بيودّيك على طول لصفحة تعديل الـ SOP الجديدة عشان تكمل بياناتها.

## 6. تطويرات مستقبلية مقترحة

- ⏳ **الفلو المتوازي داخل الـ SOP نفسه** (بين خطوات نفس الـ SOP، مش بين الـ SOPs) — لو احتجته لاحقًا، هيحتاج محرر رسم بياني منفصل زي اللي عملناه للخط بس على مستوى الخطوات.

- سجل مراجعات/موافقات (approval workflow) قبل ما SOP يبقى "معتمدة".
- ربط كل SOP بكود المنتج / order code زي الديكودر بتاعك.
- نسخة عرض offline (Service Worker) زي نظام تتبع العيوب.
- تتبع "آخر قراءة" لكل فني (توقيع إلكتروني إنه قرأ الـ SOP قبل التشغيل).
