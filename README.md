# نظام تسجيل الـ SOP (Standard Operating Procedures)

نظام مستقل لتسجيل تعليمات التشغيل القياسية بشكل SOP احترافي متكامل، مطابق لعناصر مستند SOP القياسي:

```
SOP
 ├── 1) البيانات الأساسية (كود تلقائي، إصدار، الخط، إعداد/اعتماد تلقائي بالاسم والتاريخ)
 ├── 5-6) المراحل → الخطوات (مباشرة بعد الخط):
 │        ├── المعدات والآلات المستخدمة + مهمات وإجراءات الوقاية (جنب بعض)
 │        ├── شرح الخطوة + صورة الخطوة
 │        ├── معيار القبول + طريقة الفحص + التكرار + الإجراء عند الرفض
 │        └── وسم "خطوة حرجة" لو لازم وقفة إلزامية
 ├── 7) السلامة العامة، 8) التعامل مع الانحرافات — في قسم "تفاصيل إضافية" بعد الخطوات
 ├── 4) الأدوات والمواد المطلوبة (عامة على مستوى الـ SOP)
 ├── 9) المراجع (معايير / رسومات هندسية)
 └── 10) سجل التعديلات — بيزيد رقم الإصدار (Rev.) بس لما تدوس زرار "💾 حفظ التعديلات"
```

مع زرين طباعة (تفصيلي وجدول Excel-style)، لوجو شركة يتضاف مرة واحدة من داخل النظام ويظهر تلقائيًا في كل مكان، وفوتر ثابت (كود الفورم) بيتكرر في كل صفحة مطبوعة.

الستاك: Supabase (DB + Auth + Storage) + JavaScript عادي (بدون build step) + GitHub Pages — نفس نمط مشاريعك التانية.

---

## 1. تجهيز Supabase

1. من [supabase.com](https://supabase.com) اعمل مشروع جديد (أو استخدم مشروع موجود).
2. روح لـ **SQL Editor** وشغّل الملفات بالترتيب:
   - `sql/001_init_schema.sql` أولاً
   - `sql/002_sop_details.sql`
   - `sql/003_factory_sheet_fields.sql`
   - `sql/004_auto_code_and_step_fields.sql` — بيضيف توليد الكود التلقائي من اسم الخط، وحقول الخطوة الجديدة (طريقة الفحص، التكرار، الإجراء عند الرفض)
   - `sql/005_app_settings.sql` — بيضيف جدول إعدادات عامة (لحفظ لوجو الشركة مرة واحدة)
   - `sql/006_station_flow_and_video_upload.sql` — بيضيف رقم محطة فريد لكل مرحلة، و Storage bucket لرفع الفيديوهات
   - `sql/007_sop_level_video.sql` أخيرًا — بينقل الفيديو ليكون واحد لكل SOP بدل كل خطوة
3. من **Project Settings > API** انسخ:
   - `Project URL`
   - `anon public key`
4. افتح `js/supabase-config.js` وحط القيمتين مكان:
   ```js
   const SUPABASE_URL = "https://YOUR-PROJECT-REF.supabase.co";
   const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
   ```

### الأدوار (Roles)
كل حساب جديد بيتسجل بصلاحية `viewer` تلقائيًا (مشاهدة فقط). عشان تدي حد صلاحية `editor` أو `admin`:

```sql
update public.profiles set role = 'admin' where id = 'USER_UUID_HERE';
```

هتلاقي الـ UUID من **Authentication > Users** في Supabase Dashboard.

- **viewer**: يشوف ويطبع بس.
- **editor**: يضيف/يعدل SOPs، مراحل، خطوات، صور.
- **admin**: زي editor + يقدر يحذف SOP كامل.

## 2. تشغيل محلي / رفع على GitHub Pages

مفيش build step — الموقع HTML/CSS/JS عادي.

**محلي:** افتح المجلد بأي static server (مثلاً إضافة Live Server في VS Code) أو:
```bash
npx serve .
```

**GitHub Pages:**
1. ارفع محتوى المجلد كامل (`index.html`, `css/`, `js/`) لريبو جديد على GitHub.
2. Settings > Pages > اختار الـ branch (main) و root.
3. خلال دقيقة الموقع هيبقى شغال على `https://username.github.io/repo-name/`.

## 4. طريقة الاستخدام

1. سجّل حساب (Sign up) من الصفحة الرئيسية.
2. اطلب من نفسك (أو من admin) ترقية صلاحيتك لـ editor عن طريق SQL query فوق.
3. من "+ SOP جديد" هيتفتح فورم بسيط: اكتب **اسم الخط** (مثال: "التجميع النهائي")، احفظ — الكود بيتولّد لوحده على طول (زي `SOP-FINAL-ASSEMBLY-001`).
4. تحت زرار **"💾 حفظ التعديلات (تحديث الإصدار)"** — ده الزرار الوحيد اللي بيزوّد رقم الإصدار (Rev.). أي حفظ تاني (خطوة، مرحلة، صورة، أداة...) بيتخزن فورًا في قاعدة البيانات من غير ما يزوّد الإصدار، لحد ما تدوس عليه.
5. تحت كده على طول قسم **خطوات التشغيل** — زرار "+ إضافة مرحلة جديدة" بيضيفلك أول خطوة فيها تلقائيًا تكتب فيها على طول. جوه كل خطوة: العنوان، **المعدات والآلات المستخدمة** و**مهمات وإجراءات الوقاية (السيفتي)** جنب بعض، شرح الخطوة، صورة الخطوة، معيار القبول، طريقة الفحص، التكرار، الإجراء عند الرفض.
6. تحت الخطوات، قسم **"تفاصيل إضافية"** (السلامة العامة/الانحرافات)، وبعده **الأدوات والمواد** و**المراجع** — اختياريين، تقدر تملاهم في أي وقت.
7. من **admin** تقدر تدوس **"✅ اعتماد الـ SOP"** — بيسجّل اسمك وتاريخ اليوم تلقائيًا كتاريخ اعتماد، ويطلع مطبوع على الورقة.
8. اضغط "عرض / طباعة" لمعاينة الشكل النهائي، وهتلاقي زرارين طباعة:
   - **"طباعة / PDF"**: نسخة تفصيلية كاملة (ممكن تمتد لأكتر من صفحة).
   - **"📊 نسخة الجدول (Excel)"**: جدول أفقي — صف لكل خطوة، وكل تفصيلة في خانة منفصلة، بالظبط زي شيت إكسيل. الصور بحجم موحّد وواضح، والتقرير بيمتد لأكتر من صفحة تلقائيًا لو الخطوات كتيرة.

**الترجمة التلقائية:** أي حقل عنوان بالعربي (اسم الـ SOP / المرحلة / الخطوة) — لما تكتبه وتخرج منه، لو حقل الإنجليزي جنبه فاضي هيتترجم تلقائيًا (خدمة مجانية بدون مفتاح API). لو الترجمة مش دقيقة تقدر تعدلها يدوي في أي وقت.

**الكود التلقائي:** مفيش إدخال يدوي لكود المستند ولا لتاريخ الإعداد ولا لاسم اللي بيعمل التعديل. اكتب اسم الخط واحفظ، والنظام بيولّد كود زي `SOP-FINAL-ASSEMBLY-001` تلقائيًا. "أنشأ بواسطة" و"آخر تعديل بواسطة" بياخدهم النظام من حساب المستخدم المسجّل دخول تلقائيًا.

**ترتيب حقول الخطوة** بقى: 1) الخطوة 2) المعدات والآلات المستخدمة + السيفتي جنب بعض 3) شرح الخطوة 4) صورة الخطوة 5) معيار القبول 6) طريقة الفحص 7) التكرار 8) الإجراء عند الرفض. حقل "معيار الرفض" اتشال خالص (معيار القبول بيغطيه). أي بيانات إضافية (المسؤول، المواصفة الفنية، كود العيب، الفيديو) في قسم "بيانات إضافية (اختياري)" قابل للطي.

**تبسيط إضافة المراحل:** لما تضيف مرحلة جديدة، النظام بيضيفلك أول خطوة فيها على طول. قسم "مسار المراحل" (الصناديق والأسهم) اتشال خالص؛ ترتيب المراحل بيتحكم فيه بزراري ▲▼ جنب كل مرحلة.

**فيديو الـ SOP:** فيديو واحد بس لكل SOP (مش لكل خطوة) — هتلاقي حقله في البيانات الأساسية فوق. تقدر إما تلصق رابط فيديو خارجي (يوتيوب/درايف)، أو تدوس "📹 رفع فيديو" وترفع ملف مباشرة من جهازك (بيتخزن في Supabase Storage). بيظهر في صفحة العرض كرابط، وفي الطباعة كـ QR code مرة واحدة فوق الصفحة.

**رقم المحطة ولوحة الفلو:** كل مرحلة دلوقتي ليها حقل "رقم المحطة" (رقم صحيح، لازم يكون فريد جوه نفس الـ SOP — لو كررت رقم موجود هيرفض الحفظ ويطلعلك تنبيه). في صفحة عرض أي SOP، هتلاقي "لوحة المراحل (Flow)" فوق قسم الخطوات، بترسم المراحل كصناديق مرتبطة بأسهم **مرتبة حسب رقم المحطة** (مش ترتيب الإضافة).

**لوجو الشركة:** من صفحة قائمة الـ SOPs، الـ admin بس بيشوف قسم "لوجو الشركة" فوق — دوس "رفع اللوجو" واختار الصورة **مرة واحدة بس**. بعد كده هيظهر تلقائيًا على يسار كل ورقة مطبوعة (تفصيلية أو جدول) في كل الـ SOPs، من غير ما تحتاج تضيفه تاني.

**الفوتر الثابت:** تحت كل صفحة مطبوعة (في التقريرين الاتنين) بيتحط سطر ثابت: "Midea Electric Egypt — FR-08-05-01-05 — Issue: 1.0 — ISO 9001:2015"، بيتكرر في كل صفحة تلقائيًا. لو حبيت تغيّره، هتلاقيه في دالة `buildFormFooter()` في `js/pdf-export.js`.

## 5. ملاحظات فنية

- **الصور** بتتخزن في Supabase Storage bucket اسمه `sop-images` (public bucket، الرابط بيتحفظ في جدول `step_images`).
- **الفيديو** مش بيترفع على النظام — بس رابط خارجي (YouTube / Google Drive) بيتحط في العمود `video_url`، وبيظهر كـ QR code في نسخة الـ PDF.
- **الطباعة**: بتستخدم `jsPDF` + `html2canvas` لعمل A4 PDF فيه كل المراحل والخطوات والصور. لو عندك عدد صور كبير جدًا في SOP واحد، التصدير ممكن ياخد كذا ثانية — فيه progress message بيتغير على الزرار نفسه.
- **RLS**: أي مستخدم مسجل دخول (authenticated) يقدر يقرأ كل الـ SOPs. الكتابة (إضافة/تعديل/حذف) محصورة على `editor` و `admin` بس، عن طريق `is_editor_or_admin()` function جوه الـ policies.

## 6. تطويرات مستقبلية مقترحة

- سجل مراجعات/موافقات (approval workflow) قبل ما SOP يبقى "معتمدة".
- ربط كل SOP بكود المنتج / order code زي الديكودر بتاعك.
- نسخة عرض offline (Service Worker) زي نظام تتبع العيوب.
- تتبع "آخر قراءة" لكل فني (توقيع إلكتروني إنه قرأ الـ SOP قبل التشغيل).
