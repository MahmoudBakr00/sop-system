# نظام تسجيل الـ SOP (Standard Operating Procedures)

نظام مستقل لتسجيل تعليمات التشغيل القياسية بشكل SOP احترافي متكامل، مطابق لعناصر مستند SOP القياسي:

```
SOP
 ├── 1) البيانات الأساسية (كود، إصدار، خط/محطة، إعداد/مراجعة/اعتماد)
 ├── 2) الهدف والنطاق (Purpose & Scope)
 ├── 3) المسؤوليات — مسؤول كل خطوة (Operator / Supervisor / QC / Maintenance)
 ├── 4) الأدوات والمواد المطلوبة (عدد، أجهزة قياس، مواد خام)
 ├── 5-6) المراحل → الخطوات:
 │        ├── الوصف / طريقة التنفيذ
 │        ├── مواصفة فنية (Torque / أبعاد)
 │        ├── المتطلبات الخاصة بالخطوة
 │        ├── معيار القبول / الرفض + كود العيب (ربط بنظام تتبع العيوب)
 │        ├── صور متعددة + رابط فيديو (فحص/تجميع)
 │        └── وسم "خطوة حرجة" لو لازم وقفة إلزامية
 ├── 7) السلامة (تحذيرات + PPE) — عام وخاص بكل خطوة
 ├── 8) التعامل مع الانحرافات (يتربط بمنطق الـ Andon)
 ├── 9) المراجع (معايير / رسومات هندسية)
 └── 10) سجل التعديلات — بيتسجل تلقائيًا مع كل حفظ ويزوّد رقم الإصدار (Rev.)
```

مع زر **طباعة / PDF** يصدّر الـ SOP بالكامل (كل الأقسام + المراحل والخطوات والصور) كملف PDF منسّق، ويحول رابط الفيديو في كل خطوة إلى **QR code** يُمسح من على الورقة المطبوعة.

**ملاحظة عن الإصدار (Revision):** أي حفظ ناجح — سواء تعديل بيانات أساسية، إضافة/تعديل/حذف مرحلة أو خطوة أو صورة أو أداة أو مرجع — بيستدعي تلقائيًا دالة `bump_sop_revision()` في قاعدة البيانات، فبتزيد `version` وبيتسجل سطر جديد في جدول `sop_revisions` (مين عمل التعديل ومتى ووصف مختصر). تقدر تتابع كل ده من قسم "سجل التعديلات" في آخر صفحة العرض/التعديل.

الستاك: Supabase (DB + Auth + Storage) + JavaScript عادي (بدون build step) + GitHub Pages — نفس نمط مشاريعك التانية.

---

## 1. تجهيز Supabase

1. من [supabase.com](https://supabase.com) اعمل مشروع جديد (أو استخدم مشروع موجود).
2. روح لـ **SQL Editor** وشغّل الملفات بالترتيب:
   - `sql/001_init_schema.sql` أولاً
   - `sql/002_sop_details.sql`
   - `sql/003_factory_sheet_fields.sql`
   - `sql/004_auto_code_and_step_fields.sql` أخيرًا — بيضيف توليد الكود التلقائي من اسم المحطة، وحقول الخطوة الجديدة (طريقة الفحص، التكرار، الإجراء عند الرفض)
3. من **Project Settings > API** انسخ:
   - `Project URL`
   - `anon public key`
4. افتح `js/supabase-config.js` وحط القيمتين مكان:
   ```js
   const SUPABASE_URL = "https://YOUR-PROJECT-REF.supabase.co";
   const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
   ```

### الأدوار (Roles)
كل حساب جديد بيتسجل بصلاحية `viewer` تلقائيًا (مشاهدة فقط). عشان تدي حد صلاحية `editor` أو `admin`:

```sql
update public.profiles set role = 'admin' where id = 'USER_UUID_HERE';
```

هتلاقي الـ UUID من **Authentication > Users** في Supabase Dashboard.

- **viewer**: يشوف ويطبع بس.
- **editor**: يضيف/يعدل SOPs، مراحل، خطوات، صور.
- **admin**: زي editor + يقدر يحذف SOP كامل.

## 2. تشغيل محلي / رفع على GitHub Pages

مفيش build step — الموقع HTML/CSS/JS عادي.

**محلي:** افتح المجلد بأي static server (مثلاً إضافة Live Server في VS Code) أو:
```bash
npx serve .
```

**GitHub Pages:**
1. ارفع محتوى المجلد كامل (`index.html`, `css/`, `js/`) لريبو جديد على GitHub.
2. Settings > Pages > اختار الـ branch (main) و root.
3. خلال دقيقة الموقع هيبقى شغال على `https://username.github.io/repo-name/`.

## 4. طريقة الاستخدام

1. سجّل حساب (Sign up) من الصفحة الرئيسية.
2. اطلب من نفسك (أو من admin) ترقية صلاحيتك لـ editor عن طريق SQL query فوق.
3. من "+ SOP جديد" هيتفتح فورم بيانات الـ SOP بالكامل بالترتيب:
   - **البيانات الأساسية**: كود المستند، عنوان عربي/إنجليزي، خط الإنتاج، المحطة، إعداد/مراجعة/اعتماد (بالاسم والتاريخ).
   - **الهدف والنطاق**.
   - **الأدوات والمواد المطلوبة**: قائمة تضيفها مرة واحدة وتتكرر ظهورها في العرض والطباعة.
   - **السلامة (PPE) والتعامل مع الانحرافات**: نص عام يظهر أعلى كل SOP.
4. تحت كده زرار "+ إضافة مرحلة جديدة" — كل مرحلة فيها زرار "+ إضافة خطوة".
5. جوه كل خطوة: العنوان، الوصف، **المسؤول عن الخطوة**، **مواصفة فنية** (Torque/أبعاد)، المتطلبات (Enter لإضافة chip)، **معيار القبول/الرفض**، **كود العيب**، وسم "خطوة حرجة"، ملاحظة سلامة خاصة، رفع صور متعددة، ورابط الفيديو.
6. **المراجع** بتتضاف في قسم منفصل تحت الأدوات.
7. اضغط "عرض / طباعة" لمعاينة الشكل النهائي (بيشمل كل الأقسام + سجل التعديلات في الآخر)، وهتلاقي زرارين طباعة:
   - **"طباعة / PDF"**: نسخة تفصيلية كاملة (ممكن تمتد لأكتر من صفحة).
   - **"📊 نسخة الجدول (Excel)"**: جدول أفقي — صف لكل خطوة، وكل تفصيلة (المعدات، الشرح، الصورة، معيار القبول، طريقة الفحص، التكرار، معيار الرفض، الإجراء عند الرفض، السيفتي) في خانة منفصلة، بالظبط زي شيت إكسيل. الصور بحجم موحّد وواضح في كل الخطوات، والتقرير بيمتد لأكتر من صفحة تلقائيًا لو الخطوات كتيرة (عشان الوضوح مش بيتأثر بعدد الخطوات).

**الترجمة التلقائية:** أي حقل عنوان بالعربي (اسم الـ SOP / المرحلة / الخطوة) — لما تكتبه وتخرج منه (Tab أو دوس بره الحقل)، لو حقل الإنجليزي جنبه فاضي هيتترجم تلقائيًا (خدمة مجانية بدون مفتاح API). لو الترجمة مش دقيقة تقدر تعدلها يدوي في أي وقت.

**الكود التلقائي:** مفيش إدخال يدوي لكود المستند ولا لتاريخ الإعداد/المراجعة ولا لاسم اللي بيعمل التعديل. اكتب اسم المحطة واحفظ، والنظام بيولّد كود زي `SOP-EXTRUDER-001` تلقائيًا. "أنشأ بواسطة" و"آخر تعديل بواسطة" بياخدهم النظام من حساب المستخدم المسجّل دخول تلقائيًا وقت كل حفظ. الاعتماد بقى زرار مخصص (admin بس) بيسجّل اسم المعتمِد وتاريخ اليوم تلقائيًا لما تدوسه.

**ترتيب حقول الخطوة** بقى: 1) الخطوة 2) المعدات والآلات المستخدمة 3) شرح الخطوة 4) صورة الخطوة 5) معيار القبول 6) طريقة الفحص 7) التكرار 8) معيار الرفض 9) الإجراء عند الرفض 10) السيفتي. أي بيانات إضافية (المسؤول، المواصفة الفنية، كود العيب، الفيديو) اتنقلت لقسم "بيانات إضافية (اختياري)" قابل للطي تحت.

**تبسيط إضافة المراحل:** لما تضيف مرحلة جديدة، النظام بيضيفلك أول خطوة فيها على طول من غير ما تدوس زرار زيادة — تكتب فيها على طول. قسم "مسار المراحل" (الصناديق والأسهم اللي كانت بتظهر فوق المراحل في صفحة التعديل والعرض) اتشال خالص تبسيطًا للواجهة؛ ترتيب المراحل دلوقتي بيتحكم فيه بس بزراري ▲▼ جنب كل مرحلة.

كل حفظ (حتى لو تعديل بسيط) بيزوّد رقم الإصدار تلقائيًا — تقدر تتابعه من "سجل التعديلات" في آخر الصفحة.

## 5. ملاحظات فنية

- **الصور** بتتخزن في Supabase Storage bucket اسمه `sop-images` (public bucket، الرابط بيتحفظ في جدول `step_images`).
- **الفيديو** مش بيترفع على النظام — بس رابط خارجي (YouTube / Google Drive) بيتحط في العمود `video_url`، وبيظهر كـ QR code في نسخة الـ PDF.
- **الطباعة**: بتستخدم `jsPDF` + `html2canvas` لعمل A4 PDF فيه كل المراحل والخطوات والصور. لو عندك عدد صور كبير جدًا في SOP واحد، التصدير ممكن ياخد كذا ثانية — فيه progress message بيتغير على الزرار نفسه.
- **RLS**: أي مستخدم مسجل دخول (authenticated) يقدر يقرأ كل الـ SOPs. الكتابة (إضافة/تعديل/حذف) محصورة على `editor` و `admin` بس، عن طريق `is_editor_or_admin()` function جوه الـ policies.

## 6. تطويرات مستقبلية مقترحة

- سجل مراجعات/موافقات (approval workflow) قبل ما SOP يبقى "معتمدة".
- ربط كل SOP بكود المنتج / order code زي الديكودر بتاعك.
- نسخة عرض offline (Service Worker) زي نظام تتبع العيوب.
- تتبع "آخر قراءة" لكل فني (توقيع إلكتروني إنه قرأ الـ SOP قبل التشغيل).
